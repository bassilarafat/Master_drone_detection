# إعدادات تدريب اللاب — نسخة 3 للمراجعة قبل التشغيل

> تم تحديث تنفيذ الاستكمال بعد هذه المسودة: المرجع الحالي هو `docs/HOW_TO_RESUME_CONTROLLED_TRAINING.md` و`docs/YOLO26_V3_VALIDATION_REPORT.md`. التنفيذ الحالي يحتفظ بكل epoch باستخدام `save_period: 1`، ويضم هوية البروتوكول داخل checkpoint، ويبحث في ملفات epoch عند فساد `last.pt`. وصف النسخ الدورية أدناه يمثل المسودة السابقة فقط.

**الحالة: مسودة إعدادات وتنفيذ، وليست رنًا بدأ أو إعدادات سرعة تم قياسها.** توقّف رن v2 بطلب الباحث بعد 3 epochs مكتملة. احتُفظ بالأوزان والنتائج واللوجات؛ لا تدمج هذه المحاولة مع نتائج النسخة الجديدة.

## الإعدادات المقترحة

| الإعداد | المقترح لكل من E0 وE1 |
|---|---|
| الحجم | 960 |
| Physical batch | 4 |
| Gradient accumulation | 4، مع nominal batch = 16 |
| AMP | مفعّل |
| Workers | 2 |
| Optimizer | MuSGD، lr0=0.01 |
| Epochs | 100 |
| Seeds | 17، 42، 123 |
| Initialization | public YOLO26s backbone modules 0–10؛ بقية الشبكة حسب البذرة |
| البيانات | Clean_v2 Train وValidation؛ لا Test inference |

هذه قيم مرشحة لتحسين الاستغلال؛ لم يُقَس بعد زمنها أو استهلاك ذاكرتها على المعماريتين. يلزم فحص batch4 وAMP لكلتيهما قبل اعتمادها وختمها. أي تعديل يتم قبل الرن ويطبق على الاثنين. تغيير physical batch يؤثر في BatchNorm؛ لا يُعد مطابقًا حسابيًا لـbatch1 لمجرد ثبات nominal batch.

ملف المراجعة: `configs/paper/yolo26_laptop_v3.review.yaml`.

## عند إغلاق اللاب أو انقطاع الكهرباء

- الحفظ يتم بعد كل epoch مكتمل. لا تُحتفظ بنسخة مستقلة لكل epoch لتجنب استهلاك عدة جيجابايت؛ يحتفظ النظام بآخر نسخة ونسخة سابقة احتياطية، إضافة إلى ملفات Ultralytics المعتادة.
- تُكتب النسخة الاحتياطية في ملف مؤقت ثم تُستبدل ذريًا؛ إذا تلفت أحدث نسخة عند الاستكمال، يحاول النظام النسخة السابقة القابلة للقراءة وبها optimizer state.
- الاستكمال يحافظ على هوية التجربة والبذرة والإعدادات، ويستخدم حالة التدريب المحفوظة، وليس تشغيل تدريب جديد من weights فقط.
- لو أُغلق اللاب فجأة أثناء epoch، قد يُعاد الجزء غير المحفوظ من ذلك الـepoch. لا يوجد ادعاء باستكمال من نفس minibatch أو تطابق bit-for-bit مع رن لم ينقطع؛ تُسجل كل جلسة انقطاع/استكمال.
- عند طلب pause، ينتظر التوقف نهاية الـepoch لحفظه. إذا أغلقت الجهاز قبل ذلك، يكون الرجوع لآخر نسخة محفوظة.
- التدريب لا يستمر والجهاز مطفأ أو في Sleep. لم تتغير إعدادات غطاء اللاب أو الطاقة أو أي خدمة لبدء التدريب تلقائيًا عند تشغيل Windows.
- الملفات محلية؛ إغلاق اللاب لا يمسحها، لكن حماية البيانات من تلف القرص تحتاج نسخة احتياطية خارجية منفصلة.

## ملفات التشغيل

`scripts/laptop_training.ps1` يفتح افتراضيًا على **check** فقط؛ لا يبدأ تدريبًا بمجرد تشغيله.

من PowerShell داخل مجلد المشروع:

```powershell
# مراجعة الإعدادات — بلا تدريب
.\scripts\laptop_training.ps1 -Mode check -Arm E0 -Seed 17

# بعد مراجعة الباحث وفحص hardware ناجح وختم الإعدادات فقط:
.\scripts\laptop_training.ps1 -Mode seal
.\scripts\laptop_training.ps1 -Mode start -Arm E0 -Seed 17

# طلب توقف عند نهاية الـepoch الجاري:
.\scripts\laptop_training.ps1 -Mode pause -Arm E0 -Seed 17

# بعد فتح اللاب مجددًا، بنفس الإعدادات والبذرة:
.\scripts\laptop_training.ps1 -Mode resume -Arm E0 -Seed 17
```

أمر seal يرفض التنفيذ قبل وجود تقرير hardware ناجح للمعماريتين مرتبط ببصمة نفس ملف الإعدادات. هذا التقرير لم يُنشأ بعد، وأي start/resume يرفض العمل دون الختم؛ لذلك لا تعتبر الملف المرفق تصريحًا بأن خطوة فحص السرعة والذاكرة قد اكتملت.

النتائج الجديدة ستكون تحت `04_experiments/controlled_yolo26_v3/`، منفصلة عن v2. تحفظ اللوجات لكل جلسة وملف `state.json` للحالة، ولا تبدأ بقية الأذرع أو البذور تلقائيًا.

## ما تم اختباره وما لم يُختبر

اختبارات دون تدريب تتحقق من تطابق إعدادات E0/E1، وبقاء النسخة القديمة عند فشل الاستبدال الذري، والرجوع من checkpoint تالف إلى النسخة السابقة، ورفض inference-only checkpoints للاستكمال. تم فحص الصياغة البرمجية وقراءة ملف الإعدادات. **لم يبدأ تدريب v3، ولم يُختبر بعد استكمال GPU كامل أو انقطاع كهرباء فعلي**؛ يتم استكمال التحقق الفني بعد مراجعة الباحث وقبل الرن البحثي.

الحزمة ZIP للمراجعة تُستخدم داخل المشروع الحالي؛ لا تحتوي على الداتا أو الأوزان أو بيئة Python، وليست نسخة مستقلة عن المشروع.
